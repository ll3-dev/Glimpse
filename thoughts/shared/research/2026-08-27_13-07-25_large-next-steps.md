## 상세 분석

### 1. 임베딩 배치 API (~1일, 저리스크)

**문제**: `useSemanticRerank`가 검색어마다 검색 결과 N개를 개별 `run_embedding` invoke — 31회 IPC 순차 발생. 사후 감사 수정(async+spawn_blocking+debounce+상한 30)으로 증상은 완화됐으나 구조 비용은 그대로.

**현황**:
- `apps/desktop/src-tauri/src/llm/engine.rs` — 임베딩이 per-call 생성(컨텍스트 재사용 구조 아님). 임베딩 컨텍스트는 `n_ctx`, poolingType 세팅 필요(llama-cpp-2 공식 임베딩 예제 패턴)
- `useSemanticRerank.ts` — debounce 250ms/MAX_EMBED_ITEMS 30/캐시(modelId 포함)/warn-once 이미 적용(5556c65)

**옵션**:
- (a) 상시 임베딩 컨텍스트 유지 → **비권장**. `LlamaContext`가 !Send여서 Tauri 상태에 못 넣음; 스레드 설계 갈아엎기.
- (b) 디스크 캐시 → **제외**. 임베딩 벡터 캐시는 stale 위험과 저장소 부담 대비 이득 적음.
- (c) **배치 명령 `run_embedding_batch`(권장)** — engine.rs에 `embeddings_batch(&self, texts)` 추가(clear_kv_cache 루프), state/runtime_service 확장, commands에 async+spawn_blocking. TS service가 한 번에 배열 전송.

**공수**: ~1일(engine + runtime_service + commands + TS service 메서드 + useSemanticRerank 1회 배치 호출로 변경 + 테스트).

### 2. 모바일 semantic 검색 연결 (~0.5–1일 + UI, BYOK-first)

**문제**: 데스크톱만 의미 재정렬 지원. 모바일 검색은 키워드 매칭뿐.

**권고 경로 — BYOK-first**:
- openai-compatible `/embeddings` 엔드포인트 배열 배치 사용(사용자 BYOK 설정 재사용)
- **Anthropic은 embedding API 없음** — provider 능력 분기 필요
- 옵트인 토글 + 프라이버시 명시(선택 항목 내용이 원격 API로 전송됨) 필수
- 온디바이스(bridge-rust 임베딩)는 차후 옵션(~2–3일): LoadModelOptions.embedding/poolingType, nomic 모델 mobileProfile 필요, "Context is busy" 동시성 주의

**재사용 자산**: shared semantic/rankBySemanticSimilarity, `useSemanticRerank`를 packages/hooks로 embed-fn 주입형으로 승격하면 양쪽 소비 가능.

**공수**: 서비스+hooks 승격 ~0.5일, 모바일 settings 옵트인 토글+프라이버시 문구+API 클라이언트 ~0.5–1일.

### 3. CI 게이트 강화 — 정정 포함 단계적 접근

**핵심 정정**: "네이티브 게이트 없음" 가정은 틀림. 60aca23(8/21)에서 iOS xcodebuild(simulator, unsigned)·Android bundleRelease(unsigned) 잡이 이미 존재. 실제 문제는 세 가지 운영 문제:

- **(a) 파이프라인이 8/19 이후 완전 그린 0회** — 직전 32실행 중 18 failure. 원인 3종: `unused import std::path::Path` 컴파일 에러, clippy `-D warnings` 누적 위반, iOS는 expo-modules-core × 새 Xcode 호환성 붕괴(프로젝트 코드 아님). **게이트 추가보다 복구 선행**
- **(b) bun-version 드리프트** — CI 고정 `1.3.6` vs packageManager `bun@1.4.0`
- **(c) audit high 32건 transitive**(expo/RN/eslint/vite 하위, 대부분 DoS류 노출도 낮음) — 메인 레인에 넣으면 즉시·계속 레드

**단계별 권고**:
- **P1**: 백로그 clippy/unused-import 해소 → bun-version 드리프트 제거 → audit은 주간 cron non-blocking job
- **P2**: 기존 rust job에 `tauri build --debug --no-bundle --bundles deb 한정` 스텝 추가 — cargo test와 debug 프로필 캐시 공유해 순증가분 +1–3m. 번들 단계는 주간 cron 별도 job(macOS DMG 포함 matrix)
- **P3**: Playwright + vite preview 스모크(TS only, Rust 무관, +2–3m; `isTauriRuntime()` 폴백 가드 덕에 브라우저 컨텍스트 유효). `@wdio/tauri-service` macOS E2E는 높은 세팅 비용(1일±)으로 실사용 플로우 확정 후
- **P4**: ios-release/android-release 주간 cron + path filter 격리 — 현재 33분/PR이 관측된 자주 안 바뀌는 영역에 과금되는 구조. iOS는 Xcode pin으로 수리 후 cron 운영

### 4. 델타 동기화 — 미루되 값싼 최적화는 이번에

**현행 실측(release 빌드, M-series, 혼합 픽스처)**:

| 레코드 | export | 직렬화 | 페이로드 | idle 비교 | 1건 변경 병합 |
|---|---|---|---|---|---|
| ~300 | <1ms | <1ms | 130KB | 1ms | 3ms |
| ~2,700 | 1ms | <1ms | 650KB | 6ms | 16ms |
| ~11k | 5ms | 1ms | 2.6MB | 27ms | 68ms |
| ~55k | 30ms | 8ms | 13MB | 143ms | 370ms |

Rust 병합은 수천 레코드에서 몇 ms — **문제 아님**. 지배적 비용은 러스트 밖: ① idle이어도 요청마다 데스크톱 자기 전체 export+SHA256(server.rs:263-265), ② idle이어도 업로드는 항상 전체(10k급=13MB/분 지속, 단 포그라운드 한정), ③ Hermes JSON.parse.

**설계안**:
- **A(watermark+updated_at)**: 마이그레이션 0004로 인덱스 3개만(listSince 선례 있음). 난관은 merge_exports가 완전 집합 전제 → 부분 입력을 받는 증분 적용 경로 신규 작성(prefer_candidate 행 단위 upsert + 툼스톤)이 공수의 대부분. 리스크 중: 클록 스큐 누락 창(per-peer 워터마크+24h 가드밴드+주기 full 정산으로 봉합), 페어링 재설정/import 시 워터마크 무효화. **1.5–2주**
- **B(per-record HLC 카운터)**: 5테이블 rev 컬럼+쓰기 경로 전반+prefer_candidate/clamp/fingerprint 정규화 재작성, 수렴 시맨틱 전면 재검증. **3–5주, 현재 규모엔 과잉**

**v1→v2 버전업 경로**(할 때): additive만(SyncRequest `sinceWatermark?` optional + 응답 `delta?` + snapshot 유지). 배포 순서: 모바일 먼저(`>=` 허용 반전) → 데스크톱. `deny_unknown_fields` 없어 구 서버 무시.

**권고: 미룰 가치 > 할 가치.** 근거: (1) should_skip_merge 수리로 지배적 비용(idle 전체 DELETE+재삽입) 제거됨, Rust 병합은 몇 ms. (2) 남은 비용은 값싼 최적화 3가지로 80% 해결: a) 자기 해시를 병합 직전으로 순서 변경, b) 더티 플래그로 idle export 생략, c) zstd 압축 페이로드(양단 같은 Rust; 13MB→~1MB). 합산 수 일 공수. (3) 실질 트리거는 "메시지 축적으로 중앙값 페이로드 1–2MB 초과" — 추세 관찰 후 A안을 1.5–2주 슬롯으로 실행.

**델타 미루는 경우 이번 라운드 손에 넣을 것(값싼 3종)**:
- a) server.rs:263-265 자기 해시 계산 시점을 skip 판정 직전으로
- b) 로컬 더티 플래그(변경 없으면 exportData 생략)
- c) zstd 압축 페이로드(bridge-rust 양단 합의) — 선택적, 브릿지 regen 수반

## 아키텍처 인사이트

- 동기화 워터마크의 진짜 난관은 스키마가 아니라 **merge_exports의 완전 집합 전제** — 증분 적용 경로가 새 도메인이다
- updated_at은 병합 우선순위 클럭이면서 volatile(prefer_candidate가 skew 시 교체)이라 워터마크 의미가 미묘하게 어긋남 — 가드밴드+정산이 필수
- CI의 병목은 게이트 결여가 아니라 운영: 레드 파이프라인 위 게이트 추가 무의미, 네이티브 잡은 이미 존재
- LlamaContext !Send 제약이 임베딩 최적화 설계 공간을 상시 컨텍스트→배치 API로 좁힘
