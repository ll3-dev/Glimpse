## 1. 목표

Glimpse를 다음 경험으로 수렴시킨다.

> 메모·스크린샷·링크를 형식 선택 없이 저장하면, Glimpse가 근거 있는 연결을
> 지속적으로 갱신하고 사용자가 예상하지 못한 지식을 발견한 뒤 주변 자료를 따라
> 탐색하게 한다.

제품 성공의 우선순위는 다음과 같다.

1. 매일 부담 없이 기록하고 다시 찾을 수 있는 개인 지식 도구
2. 새 연결을 발견하는 경험
3. 연결을 따라 기존 자료를 탐색하는 경험
4. 위 경험을 뒷받침하는 로컬 우선·증분 처리·멀티플랫폼 기술 증거

그래프는 독립된 장식 화면이 아니다. 캡처, 라벨링, 검색, 추천, 복습, 동기화를
연결하는 제품의 중심 읽기 모델이다.

## 2. 현재 기준선과 확인된 결함

현재 저장소에는 다음 기반이 있다.

- 모바일·데스크톱의 보관함, 캡처, 채팅, 추천, 복습, 그래프 화면
- `Recommendation`을 그래프 엣지로 사용하는 공유 데이터 모델
- 모바일·데스크톱이 공유하는 결정론적 `layoutGraph`
- 데스크톱의 증분 그래프 생성과 태그 기반 폴백
- 추천 수락·무시·삭제 피드백과 양방향 동기화
- 로컬 LLM, BYOK, 규칙 기반 AI 라우팅

Living Graph를 확장하기 전에 다음 결함을 먼저 제거한다.

1. `apps/desktop/src/features/graph/edge-merge.ts`의 정규 쌍 키가 정렬 분기마다
   서로 다른 구분자를 사용한다. 같은 노드 쌍이 역순으로 제안되면 중복 방지가
   실패할 수 있다.
2. `analysis-state.ts`는 엣지 생성 시각을 분석 워터마크로 사용한다. 분석 결과가
   0개인 항목은 계속 `unanalyzed`로 남고, 수정되지 않은 항목도 반복 분석될 수 있다.
3. 중복 방지가 TypeScript 사전 필터에만 있어 동시에 실행되는 분석기나 동기화
   병합에 대한 저장소 불변식이 아니다.
4. 자동 생성기는 데스크톱 React 훅에 집중되어 있다. 모바일은 그래프를 읽을 수
   있지만 독립적으로 동일한 증분 분석 계약을 실행하지 못한다.
5. 현재 타원형 전체 배치는 기능 패리티에는 충분하지만 발견과 탐색을 적극적으로
   돕지는 않는다.

## 3. 선택한 접근

### 채택: 루프 우선 하이브리드

그래프 엔진과 사용자 경험을 작은 수직 슬라이스로 함께 발전시킨다. 각 단계는
실제 사용 가능한 결과와 재현 가능한 기술 증거를 동시에 남긴다.

### 채택하지 않은 접근

- **시각화 우선:** 빠르게 화려해지지만 잘못되거나 중복된 연결을 더 보기 좋게
  노출할 뿐이다.
- **엔진 우선 장기 재작성:** 경계는 깨끗해지지만 사용자가 체감하는 결과가 늦고
  기존 `Recommendation`·동기화 계약을 불필요하게 교체할 위험이 있다.

기존 모델과 브리지를 최대한 유지하고, 정확성에 필요한 저장소 불변식과 분석
워터마크만 명시적으로 추가한다.

## 4. 제품 흐름

```text
통합 캡처
  -> 텍스트·URL·이미지/OCR 정규화
  -> 라벨·요약 생성
  -> 항목을 graph-dirty 상태로 표시
  -> 증분 후보 선택
  -> AI 또는 규칙 기반 연결 근거 생성
  -> 정규 노드 쌍 단위 upsert
  -> 그래프·추천·상세 화면 캐시 갱신
  -> 발견 또는 주변 탐색
  -> 수락·무시·삭제 피드백
  -> 다음 후보 정렬과 노출에 반영
```

캡처 UI에서 사용자가 `note`, `link`, `screenshot`을 먼저 선택하게 하지 않는다.
입력 내용과 첨부를 정규화해 기존 `KnowledgeItemType`으로 저장한다. 모든 입력 형식은
저장 이후 동일한 그래프 파이프라인을 거친다.

## 5. 데이터와 저장소 불변식

### 5.1 엣지

기존 `Recommendation`을 그래프 엣지의 진실 소스로 유지한다.

- `pending`: 새로 발견했으나 아직 판단하지 않은 연결
- `accepted`: 사용자가 유지하기로 한 연결
- `ignored`, `dismissed`: 그래프에서 숨기고 같은 쌍을 자동 재생성하지 않는 연결

노드 쌍은 `min(itemAId, itemBId)`와 `max(itemAId, itemBId)`로 정규화한다. 저장소에는
두 정규 ID로 유일성 제약을 두어 UI, 동기화, 동시 분석 어느 경로에서도 같은 쌍을
중복 저장할 수 없게 한다. 기존 데이터는 마이그레이션에서 정규화하고 중복이 있으면
다음 우선순위로 하나를 보존한다.

`accepted > pending > ignored > dismissed`, 동률이면 최근 응답 또는 생성 항목.

### 5.2 분석 워터마크

엣지 유무와 분석 완료 상태를 분리한다. 항목별 분석 레코드는 최소한 다음 값을 가진다.

- 항목 ID
- 분석한 항목의 `updatedAt`
- 분석기 버전
- 분석 시각
- 결과 엣지 수
- 마지막 결과(`completed` 또는 `failed`)와 실패 횟수

연결이 0개여도 `completed`로 기록한다. 항목 수정 시 `updatedAt` 불일치로 다시 dirty가
되며, 분석기 버전이 바뀌면 필요한 항목만 재분석한다. 파생 상태이므로 데이터 내보내기와
사용자 지식의 진실 소스에는 포함하지 않는다. 엣지는 기존 동기화 계약대로 동기화한다.

### 5.3 삭제와 동기화

- 항목 삭제 또는 tombstone 병합 시 연결 소비자는 즉시 고아 엣지를 숨긴다.
- 저장소 정리 작업은 삭제된 항목에 닿는 엣지와 분석 워터마크를 멱등 제거한다.
- 동기화 충돌은 기존 결정론적 병합을 유지하고, 정규 쌍 유일성 제약을 마지막 방어선으로
  사용한다.

## 6. 공유 Living Graph 엔진

순수 계획과 플랫폼 효과를 분리한다.

### 순수 계층

`packages/features`에 다음 책임을 둔다.

- dirty 항목 판정
- 처리 배치와 재검증 후보 선택
- 정규 노드 쌍 생성
- 태그·라벨 기반 결정론적 폴백
- 사용자 피드백을 고려한 후보 제외와 정렬
- 실행 결과와 백로그 요약

### 플랫폼 어댑터

- Desktop: 로컬 LLM/BYOK/규칙 제공자, 큰 백로그 배치 처리
- Mobile: 선택된 AI target/규칙 제공자, 포그라운드 소량 처리
- Core: 워터마크와 엣지의 원자적 저장, 정규 쌍 유일성 보장

저장·수정·라벨 완료·동기화가 graph-dirty 신호를 만든다. 빠르게 연속되는 변경은
디바운스하고 같은 항목 ID를 하나로 합친다. 모바일은 백그라운드에서 모델을 무리하게
깨우지 않으며 앱 포그라운드에서 제한된 배치만 처리한다. 데스크톱이 연결되면 남은
백로그를 이어서 소화한다.

## 7. 발견과 탐색 UX

그래프 화면은 두 렌즈를 제공하되 별도 복잡한 모드 전환 UI를 만들지 않는다.

### 발견 렌즈

- 새 `pending` 연결 중 최근성과 근거 품질이 높은 항목을 `오늘의 발견`으로 노출
- 두 항목 제목, 짧은 연결 근거, 각각의 상세 진입 제공
- 수락·무시·삭제 반응을 같은 자리에서 처리
- 새 연결이 없으면 억지 추천 대신 최근 수락 연결 또는 정상 빈 상태 표시

### 탐색 렌즈

- 전체 그래프에서 노드를 누르면 선택 노드를 중앙에 두는 포커스 레이아웃으로 전환
- 1홉 이웃을 우선 표시하고 비인접 노드는 약화
- 엣지를 선택하면 근거와 반대편 항목으로 이동하는 동작 제공
- 보관함 검색 결과와 상세 화면에서 해당 노드의 포커스 그래프로 진입 가능

초기 레이아웃은 무한 물리 시뮬레이션 대신 결정론적 연결 컴포넌트·포커스 링을 쓴다.
모바일과 데스크톱이 같은 입력에서 같은 위치를 계산할 수 있고 단위·스크린샷 테스트가
가능해야 한다. 데이터가 36개를 넘으면 전체를 억지로 축소하지 않고 포커스와 검색으로
탐색한다.

## 8. 피드백과 로컬 품질 측정

외부 분석 SDK나 원격 텔레메트리를 추가하지 않는다. 기존 피드백 이벤트와 로컬 집계로
다음을 계산한다.

- 분석 대상·완료·실패·백로그 수
- 생성된 연결과 고립 항목 수
- pending/accepted/ignored/dismissed 비율
- 발견 카드에서 상세 화면으로 이동한 횟수
- 증분 처리 시간과 처리 항목 수
- 전체 재계산 대비 다시 분석하지 않은 항목 수

집계는 설정의 진단 섹션 또는 개발자용 receipt 명령으로 확인한다. 원문, API 키,
프롬프트 전체를 영수증에 기록하지 않는다. 성능 주장은 서로 다른 `generatedAt`과 입력
지문을 가진 반복 실행의 분포로 남긴다.

## 9. 오류 처리

- AI 응답 파싱 실패: 경고 기록 후 결정론적 폴백 실행
- 제공자 사용 불가: 실패로 중단하지 않고 규칙 기반 결과 사용
- 저장소 유일성 충돌: 성공한 기존 엣지를 반환하는 멱등 upsert로 처리
- 연속 실패: 지수 백오프 후 자동 재시도 중단, 수동 재시도와 진단 메시지 제공
- 앱 종료 또는 중간 실패: 완료 워터마크를 쓰지 않아 다음 실행에서 해당 배치 재개
- 동기화 중 삭제된 항목: 저장 직전 존재 여부를 다시 확인해 dangling edge 저장 차단

폴백이 0개 연결을 만들었더라도 성공적으로 분석했다면 완료 워터마크를 기록한다.

## 10. 단계별 산출물

### Phase A — 현재 그래프 마감

- 모바일 그래프 시뮬레이터 확인
- 임시 루트 리다이렉트 복원
- Phase 2 완료 문서와 자동 게이트 갱신

### Phase B — Living Graph 기반

- 정규 쌍 버그 수정과 저장소 유일성
- 명시적 분석 워터마크
- 공유 증분 계획·폴백 엔진
- 모바일·데스크톱 코디네이터
- 삭제·동기화 멱등성 테스트

### Phase C — 발견·탐색 UX

- 오늘의 발견
- 포커스 그래프와 검색→그래프 진입
- 연결 근거와 피드백 액션
- 모바일·데스크톱 패리티

### Phase D — 품질과 기술 증거

- 로컬 품질 집계
- 재현 가능한 증분 처리 receipt/benchmark
- 콜드스타트, 수정, 삭제, 동기화 시나리오 검증

### Phase E — 데스크톱 캡처 동선

- `CmdOrCtrl+Shift+K` 전역 캡처 단축키
- 트레이의 캡처·그래프·종료 메뉴
- 캡처 후 Living Graph 자동 반영

각 Phase는 이전 단계의 현재 코드와 검증 결과를 다시 읽고 별도 구현 계획으로
구체화한다. 이전 계획의 예상 결과를 현재 증거로 재사용하지 않는다.

## 11. 검증 전략

### 단위·계약

- 역순 노드 쌍과 동시 upsert 중복 방지
- 0-edge 분석 완료, 수정 후 stale, 분석기 버전 변경
- ignored/dismissed 쌍 재추천 방지
- AI 실패 폴백과 실패 워터마크
- 삭제·tombstone 후 고아 엣지 제거
- 모바일·데스크톱 동일 입력의 순수 계획 동등성

### 통합

- 캡처 → 라벨 완료 → 엣지 생성 → 쿼리 무효화 → 그래프 표시
- 모바일 캡처 → 동기화 → 데스크톱 분석 → 모바일 그래프 반영
- 같은 배치를 반복 실행해도 엣지와 피드백이 중복되지 않음
- 앱 종료 후 미완료 백로그 재개

### UI·런타임

- 모바일 시뮬레이터: 발견 카드, 노드 선택, 상세 이동, 다크 모드
- 데스크톱: 포커스 그래프, 검색 진입, 수락·무시 반영
- 실기기 필요 항목은 기존 수동 게이트 문서에 명령·기대 결과·담당자를 기록

### 공통 게이트

- `bun run lint`
- `bun run typecheck`
- `bun run desktop:typecheck`
- `bun test`
- `cargo test --workspace`
- 관련 Rust 변경 시 `cargo clippy --workspace --all-targets -- -D warnings`
- 동기화 변경 시 `cd apps/mobile && bun run sync:e2e`

## 12. 명시적 비범위

- 3D 그래프와 장식 목적의 물리 애니메이션
- 근거 없는 단일 AI 신뢰도 숫자
- 외부 분석·광고 SDK
- 클라우드 계정 또는 서버를 전제로 한 그래프 처리
- 그래프와 무관한 대규모 상태 관리·UI 리팩터
- Phase E 전의 OS 화면 캡처 권한 기반 데스크톱 스크린샷 기능

## 13. 전체 완료 기준

다음 항목을 모두 현재 상태에서 증명해야 프로그램을 완료로 본다.

1. 메모·링크·스크린샷 저장 이후 별도 수동 생성 없이 그래프가 갱신된다.
2. 0-edge 항목과 역순 쌍을 포함해 분석이 멱등이고 중복 엣지가 없다.
3. 모바일·데스크톱에서 발견과 포커스 탐색이 동작한다.
4. 연결 근거와 사용자 피드백이 표시·저장·동기화된다.
5. AI를 사용할 수 없어도 앱과 그래프 루프가 정상 동작한다.
6. 증분 처리 품질·성능을 재현 가능한 로컬 영수증으로 확인할 수 있다.
7. 전역 단축키·트레이 캡처가 기존 캡처 흐름과 그래프 갱신으로 이어진다.
8. 자동 게이트가 모두 통과하고, 계정·실기기 의존 게이트는 실제 증거 또는 명시적인
   미완료 상태로 남는다. 미완료 수동 게이트가 있으면 전체 프로그램 완료를 주장하지 않는다.
